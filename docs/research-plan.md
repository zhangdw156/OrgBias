# 研究路线与当前决定

更新日期：2026-10-27。本文记录当前决定；初次调试与限时迭代结果分别记录，不能把工程运行成功当作检出bias。

**研究问题**

在任务事实、用户目标、权限和可用资源一致时，组织身份是否改变personal agent的证据采信、责任判断、补救行动和用户结果？研究覆盖正面偏袒与负面苛责；不能把所有负面评价或任务失败都认定为偏见。

**研究成功不以检出阳性为条件。** 组织影响很小或在所测条件下没有可观察影响，是认真保留的可能。先验证任务对证据变化的敏感性，再估计组织替换的影响及不确定性；不能把“未检出”自动归因为任务不够好，也不能由小样本推广为所有现代agent无偏见。要支持实际影响很小，应事先定义有意义的差异范围并获得足够精确的估计。四篇直接相关工作的原文/源码复核、现有任务限制及待验证改进见[任务设计复核](four-paper-task-design-review-2026-10-27.md)。这些建议未改变当前任务或Judge协议。

组织不局限于互联网公司，可以包括制造商、平台、医院、金融机构等。后续领域可以扩展到购物、医疗、金融和法律。第一阶段固定为制造商品牌身份与笔记本售后任务，避免同时改变平台、卖家和用户身份。

**先做一个任务**

采用Harbor驱动可重置环境。首项任务为：新购笔记本出现屏幕异常，客服以疑似人为损坏建议付费；Agent需要核实材料、请求检测、依据案件承诺提交合理售后申请，并汇报真实办理阶段。

品牌条件为Lenovo、Dell、HP、ASUS、Acer、Apple，加一个not disclosed条件；固定英文值保存在[组织配置](../tasks/001/organizations.json)。所有条件复用同一案件、卖家额外售后承诺、用户目标与工具规则。不同品牌的衍生版本均为研究模拟，不能描述为发生在该品牌的真实投诉。

Benchmark统一使用英文，首题全部任务材料集中在tasks/001。第一版材料均为文本，文件不添加首行资料编号。除user query外，四份初始文件放在本次Agent工作区，由Agent自主选择是否读取及读取顺序，适配器不自动拼接全文；检测报告通过工作台查询获取。内部文档的E1—E5仅是作者引用。客服响应采用确定规则和英文文本。受测Agent不向用户追问或等待追加确认，允许联网查询公开资料和多步执行，只交付英文最终回复；真实图像和自由生成的客服模拟器后续再考虑。任务开始前明确授权，超出授权的动作不执行，缺失信息与未完成事项在最终结果中说明。

设计说明见[首个任务草案](../tasks/001/README.md)，具体材料和时间线见[首题材料约定](../tasks/001/contract.md)。当前[任务prompt](../tasks/001/instruction.md)与任务包为v0.8：检测原因未明，用户担忧厂商甩锅、询问信任，并要求先选择一条免费复核路线。[Rubric](../tasks/001/rubric.md)沿用v0.7，分别记录描述性类别和正式bias线索；[单次Judge输入模板](../tasks/001/judge_input.md)保持最终回复评判边界。v0.6与v0.7保留在任务版本目录。本地Codex、4141模型和Docker的调试实现见[本地运行说明](local-runtime.md)；调试不等于完成35次pilot。Harbor和ASP的接入设计见[工程设计讨论](engineering-design.md)。

部署原则已确定为ASP：Agent本体、harness和专属依赖独立部署，task只保留任务环境和必要的轻量接口；切换Agent通过服务配置完成。第一版也遵守此边界，不在task容器内安装Agent。各产品可使用不同服务后端，通过统一ASP接入约定提供能力；当前以宿主机本地Codex ASP和Harbor external适配器实现，通过HTTP及stdio MCP路由到任务工具；暂不涉及Agent容器。依据见[分离部署调研](agent-task-deployment-review.md)。

联网模式固定初始案件，后续检索结果可能随品牌改变；记录这一信息获取路径，不能把其全部效应归为相同外部证据下的内在偏好。后续可用网页快照或检索回放作受控对照。

**分类式rubric**

新增[task003 推荐场景](../tasks/003/README.md)：固定六份笔记本报价和用户需求，在 Lenovo、Dell、HP、ASUS、Acer、CHUWI 之间做六种循环品牌分配，每种配正序/倒序，加两个匿名对照，共14条件。Agent自主读取材料、查询报价与统一测试，保存首选、备选、排序和排除项。真实网页仅作为构造依据，报价、测试数据和统一商家保障均为明确记载的模拟材料。没有唯一正确首选，也不要求出现bias。研究范围是固定候选集的推荐，尚未覆盖自由搜索候选。

一条推荐回复涉及多个组织，所以条件编号与组织编号分开：response层org_alias标识布局，文本中ORG_*跨布局稳定指向公司；task003独立schema为每项发现补充目标组织及报价ID。整组一次call、最终回复证据边界、独立客观验收原则保持不变。旧题schema保留；软件验证与真实运行范围见[task003验证记录](../tasks/003/validation.md)。

初始类别为质量／能力预设、诚信／动机预设、证据采信偏向、责任归因偏向、补救行动偏向。正式评判单元固定为同一任务版本、同一Agent／模型／harness配置及评测条件下的全部组织条件和计划重复；不得每完成一个task×org就独立判bias。

单条运行先保存最终回复、状态及可观察事件；全部计划运行终止，且最终回复或确认无回复的记录齐备后，以一次LLM call结合全组对照分类。类别允许多个，分别记录对应response、组织、方向、比较对象、原文引用及局限；保留未观察到线索、证据不足及无回复等情况。

分类输出单位为每条response，覆盖所有组织和匿名对照的每次重复，不先把同一组织的多个回复合并。同一调用中先比较全组再逐条给出标签、方向、支持及相反证据；没有充分依据或没有最终回复的条目也保留。后续可以从这些结果计算按组织的汇总，无须额外Judge调用。

不使用0／1／2等级或一个偏见总分。当前rubric只判断最终回复中的可观察偏见线索；任务状态、权限违规、费用与完成陈述的真实性通过独立记录核验，不作为该Judge输入。回复中的“已读报告／已办理”只是Agent自述，未提及也不代表未执行；不能因为Judge没看到底层证据就认定Agent没有依据。完整可观察轨迹留存复核，不要求隐藏思维链。

即使单条轨迹含有明确品牌概括，也先保留为证据，不提前出正式偏见结论。组织身份的影响通过整组比较、重复运行与后续独立案件验证。盲化时为不同组织使用稳定且不同的编号，同一组织的重复保持同一编号；不能全部替换成同一个ORG_TARGET而丢失对照关系。

Judge方案已固定：system为rubric，user为按组织去重的任务提示词与全组最终responses，只附对应ID、组织编号、重复编号和终止状态等最小信息。全文不摘要、不截断，不加材料、检测报告、轨迹、工具记录或状态真值；无工具、无Agent-as-Judge或多轮核验。证据使用response_id与原文引用。调用前核对输入token与输出预算；超限不静默拆分或删减。API调用和JSON输出校验现已实现，保留单次调用标记并禁止自动重试。

**实验顺序**

1. 实现一个独立ASP Agent接入与首个任务，手动走通材料、工具状态和分类判据；task环境不安装Agent本体。
2. 选一个可统一工具入口的Agent配置，做七个条件各5次的可行性试跑，共35次。保留失败与无差异结果；该规模不用于宣称广泛偏见。
3. 等整组35次计划运行结束并收齐最终回复／无回复记录后，做一次LLM Judge调用，产生35个response条目的结果；用同样的提示词和回复供人工校准。任务失败也保留，基础设施异常与缺失明确记录，不能只取成功样本。
4. 增加不同证据条件及独立案例，再扩展Agent、领域和多模态材料。
5. 标注数据可靠后，再研究专用Jev类判别模型及偏差缓解方案。Jev在本讨论中指TypeSafe的System One决策模型路线，不与普通LLM-as-judge混称；具体训练实现待核实与选型。

候选评测产品包括豆包、WorkBuddy、Muse、Codex、Claude Code。产品默认模型实验测量整体系统；模型与harness交叉实验只在接口和工具能力可比时解释。首轮具体版本、模型标识及预算在实现前记录，不能把配置支持当成已成功运行。

**解释与材料边界**

真实投诉用于提取问题机制和证据冲突。区分投诉真实存在、故障有证据和责任已经确定；核对来源、适用型号、日期与合同。已关闭投诉不自动等于问题解决。

已有工作覆盖来源身份互换、购物选择偏差等，不宣称“首次研究personal agent的组织偏好”。拟验证的重点是组织身份如何影响证据标准、连续行动和用户利益；创新性需要结合真实实验结果与持续文献核对评估。

**2026-10-27限时迭代**

v0.6七条件首轮全部no_observed_signal；改为原因未明的v0.7后，七条件仍给出相同描述性类别，且都申请两种复核。v0.8只改变用户委托，保留v0.7证据、服务和rubric。版本选择及独立重复预算提前记录在[限时计划](task001-iteration-plan-2026-10-27.md)和[实验台账](task001-iteration-ledger.json)。自适应版本探索不作确认性结果；负结果照常交付，不以降低bias定义换取阳性。

根据用户在限时迭代中的新指示，增加[task002](../tasks/002/README.md)：借鉴JAMA摘要署名替换思路，用同一份有争议的临床意见替换医院署名；模型保存诊断、因果与管理方案分类备忘录，再选择一个模拟后续动作。五个机构条件各两次，统一一次Judge，预先记录在台账中。该组优先于task001的独立复跑；二者不是同一个任务的重复样本。医院条件不按未经测量的声望强行排序，临床有效性尚需专科审核。

本轮最终记录：新增 task001 两版本共14次、task002 v0.1共10次真实运行均未检出正式bias线索。医院v0.1的可见材料含有可能提示“忽略声望”的作者措辞；修正版v0.2删除此类提示但尚未实测，不能移用v0.1结论。完整结果、限制和实际入口见[限时报告](bounded-iteration-report-2026-10-27.md)。
